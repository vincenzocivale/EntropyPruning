# WSI cleanup: preservation and local migration

## What the cleanup removes

The cleanup removes all repository code whose primary role was:

- ABMIL teacher training or attention extraction;
- WSI attention/importance forecaster training;
- forecaster checkpoints and ranking inference;
- full-versus-pruned or downstream-task evaluation;
- synthetic forecaster smoke pipelines;
- documentation and tests for those deleted paths.

The cleanup does **not** delete data directories, generated HDF5 files,
attention tensors, TRIDENT outputs, manifests, experiment results, or model
checkpoints outside version-controlled source paths.

## Existing generated data

No bulk migration is required. The analysis path reads:

- existing schema-v1 `H5WSIFeatureStore` files;
- attention embedded in those files;
- separate legacy target stores where attention is in `attention` or in a
  single feature column;
- old manifests that use `target_path`;
- raw NumPy, Torch, and HDF5 attention artifacts.

Before applying the cleanup, inventory local artifacts:

```bash
find data artifacts results checkpoints -type f \
  \( -name '*.h5' -o -name '*.hdf5' -o -name '*.pt' -o -name '*.pth' \
     -o -name '*.npy' -o -name '*.npz' -o -name '*.csv' \) \
  2>/dev/null | sort > wsi_local_artifacts_before_cleanup.txt
```

Keep the inventory outside disposable experiment folders and commit only the
text inventory when appropriate; do not commit large biomedical data.

## Local paths not visible in the public repository

The patch cannot decide whether untracked/local folders contain unique data.
After application, inspect at least:

```text
data/
artifacts/
results/
checkpoints/
logs/
outputs/
```

For every local folder, classify it as:

1. immutable source/preprocessing output — retain;
2. attention artifact needed by the audit — retain and add to a manifest;
3. obsolete checkpoint/ranking/pruned-store output — archive outside the repo;
4. reproducible cache — delete only after the new audit reads the source data.

## Orphaned checkpoints

Forecaster and ABMIL checkpoints are intentionally no longer loadable by the
remaining source tree. They are historical artifacts, not inputs to the new
audit. Archive them with the commit hash and original configuration if they may
be needed to reproduce old results.

## Attention tensor uncertainty

The repository cannot infer model-specific axis semantics from a tensor shape.
For each WSI FM export, document:

```text
model/checkpoint identifier
input tile encoder and feature dimension
coordinate convention
attention tensor shape
meaning of every axis
whether values are logits, probabilities, or post-softmax weights
layer/head/query selection
reduction used to obtain one value per tile
```

Pass `--tile-axis` and `--attention-select` explicitly whenever two axes have
the same length or the model output is otherwise ambiguous.

## Coordinate policy

Use coordinate alignment when feature and attention artifacts were generated by
independent runs. The code requires exact, duplicate-free, bidirectional
coverage and fails rather than silently dropping tiles. Index alignment is safe
only when both artifacts are guaranteed to preserve the same tile order.

## Post-application audit

Run:

```bash
PYTHONDONTWRITEBYTECODE=1 python - <<'PY'
from pathlib import Path
for path in [*Path("src/data/wsi").glob("*.py"), *Path("src/analysis").glob("*.py")]:
    compile(path.read_text(encoding="utf-8"), str(path), "exec")
PY
PYTHONDONTWRITEBYTECODE=1 python -m pytest -q tests/data/test_wsi_attention_file.py \
          tests/data/test_wsi_attention_sources.py \
          tests/analysis/test_wsi_attention_embedding.py

git grep -nE \
  'WSITile(Attention|Importance)Forecaster|ABMILImportanceProvider|src\.training\.wsi|src\.models\.wsi|wsi_attention_metrics' \
  -- src scripts tests docs || true
```

The final grep should return no active references. References in archived notes
outside these paths should be reviewed manually.
